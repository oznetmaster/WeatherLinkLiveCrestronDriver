# WeatherLinkLiveCrestronDriver v2.0.18

This update adds OpenWeather One Call 4.0 support and reduces unnecessary cloud requests. Existing configuration fields, commands and driver identity remain unchanged. Update the existing instance; no reconfiguration is required.

The driver uses the same OpenWeather API key across services. It first tries One Call 3.0, retaining access for existing subscribers. If that service denies access, it tries 4.0; if 4.0 also denies access, it uses the free current-weather and reduced five-day forecast endpoints. Account subscriptions determine access. Rate limits, transient service failures and network failures do not trigger service fallback.

Current conditions and daily forecasts are requested together. The driver does not request hourly forecasts. A successful One Call 3.0 snapshot needs one request; 4.0 needs two. Automatic selection can also make an access-denied request while choosing a service. Cloud attempts, including failures, are spaced by at least ten minutes between configuration changes. Local station polling retains its own interval.

Runtime dependencies are SimpleWeatherClient 2.0.0 and WeatherLinkLiveLibrary 2.0.0. Both use typed System.Text.Json models. The full Newtonsoft.Json and log4net libraries are no longer merged into the driver; Crestron's own platform dependencies are unchanged.

An OpenWeather API key is still required by this driver version. A local WeatherLink Live device is optional: without one, OpenWeather supplies both current conditions and forecasts. Station-only operation without an API key is not included in this update.
